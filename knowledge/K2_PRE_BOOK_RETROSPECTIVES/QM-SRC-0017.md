## 1. Why this book now

This source is chosen not because it looks authoritative, but because the current project needs an independent modern system capable of attacking several unresolved objects left by Liang / Shantiandao / Yao Xuesheng work.

Primary attack questions:

1. Does it define star/door state systems in a way that conflicts with or narrows the current source convergence?
2. Does it treat旺相休囚 as classification only, or does it make an explicit effect-size / weighting claim?
3. Does it give a genuinely different setup / time-boundary / layout method that would force the current source profile to split further?
4. Does it provide non-Jiazi worked plates capable of contradicting the current full-rotation implementation rather than merely supporting it?
5. Does its use-god / Role Map system remain fixed by question type, or does it already contain conditional/contextual role relations?
6. Does it offer a simpler model that could make parts of `反证情境压缩法 v0.3-alpha` unnecessary?

The book is therefore an **attack source**, not a confirmation source.

## 2. Inherited assumptions at risk

### A. Context reasoning may be over-engineered

Current project assumption:

`context -> narrower role/meaning/branch space`

Risk: a simpler source-fixed role system may prove more reproducible than the current contextual Role Map machinery. If so, current context protocol must narrow rather than defend complexity.

### B. Star-state classifications may be mistaken for one shared system

Liang and Shantiandao show apparent convergence around九星旺相休囚 terminology. Risk: this may be shared lineage rather than independent agreement, or another system may define different season/month objects or operational use.

### C. The current Shantiandao rotation profile may be over-fitted

It reproduces selected worked plates and survives some negative controls, including a selected Yao Xuesheng cross-source witness. Risk: another independent worked plate may systematically disagree in star/door/deity movement, center host, chief-door count or setup assumptions.

### D. “Object Type Safety” could become a meta-rule that only names ambiguity

Sequence / Representation / Semantic object separation has prevented real errors. Risk: if every conflict is merely split into more object labels without reducing uncertainty or improving implementation, the framework itself becomes complexity accumulation.

### E. `反证情境压缩法` may mainly improve auditability, not prediction

Current strongest evidence is methodological/engineering. Risk: source reading may reveal that the theory is repackaging ordinary disciplined analysis without providing additional predictive discrimination. This must be allowed to result in `MERGE / NARROW / DELETE`.

## 3. Historical errors to actively look for

Do not repeat:

- `book says -> true`;
- `two books agree -> independently validated`;
- `case looks convincing -> rule supported`;
- `source table reproduced -> full method correct`;
- `context makes story richer -> contextual method stronger`;
- `more fields -> more rigorous`;
- `CI green -> oracle correct`;
- `old rule survived many versions -> deserves retention`.

Special visual risk for this 419-page scan:

`Visual Presence != Semantic Association`.

## 5. What would force theory change

A single book does not create Empirical Support, but it can force **theory scope** change if it exposes conceptual defects.

Theory must `NARROW / REVISE / SPLIT` if:

- Context Compression cannot be applied without importing meanings not fixed before reading the case;
- source-fixed Role Map is materially simpler and equally expressive for the claimed problem domain;
- the current object taxonomy cannot represent a source algorithm without ad-hoc exceptions;
- a source-defined worked plate shows the current implementation profile was over-generalized beyond its stated scope;
- a current “universal” source statement is contradicted by a clearly different method family.

Theory should `DELETE / MERGE` a component if this source plus existing evidence shows the component adds terminology but no new executable distinction.

## 6. What is NOT enough to force theory change

Do **not** upgrade/downgrade the theory merely because:

- the author prefers a method;
- a case is narrated as successful;
- many tables look systematic;
- a rule resembles current thinking;
- a rule sounds more ancient/traditional;
- the source gives deterministic confidence;
- the source disagrees without comparable method context;
- a modern term appears on one page;
- a visually impressive chart matches one sparse anchor.

Those increase Source knowledge only.
