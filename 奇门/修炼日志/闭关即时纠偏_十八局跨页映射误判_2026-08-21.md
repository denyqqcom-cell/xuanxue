# 闭关即时纠偏：十八局跨页映射误判 — 2026-08-21

性质：MAIN-REVIEWER ERROR CORRECTION / SOURCE-FIDELITY AUDIT

## 一、错误是什么

上一轮主审把梁湘润《奇门遁甲入门》PDF p32-p49 当成“一个 PDF raster = 一个语义页面”，并把同一 raster 右侧可见的“某某局图”标题直接配给左侧的大表。

结果造成：

- 十八局 fixture 整体出现一局位移；
- 阳遁五、六局又被 PDF p35/p36 的扫描顺序交换进一步干扰；
- p49 被误判为“可见陰遁一局圖标题，但主表缺失”；
- 我甚至把这个误判写进 fixture Gate、PR 描述和闭关内省，差点把**主审错误包装成来源异常**。

这不是书的错，是我的页面语义识别错。

## 二、为什么第一次视觉审核仍然会错

我之前把 `VISUAL_REQUIRED` 理解得还不够深。

“我真的看过图”只能防止 OCR/文本层冒充视觉阅读，却不能保证：

- 我理解了扫描页的版面拓扑；
- 我知道左右两张印刷页属于什么关系；
- 我没有把邻页标题错配给当前表；
- PDF 文件顺序和印刷页顺序完全一致。

这次 p35/p36 的印刷页号顺序与 PDF 顺序不一致，更证明：

`Visual Presence != Semantic Association`

以及：

`Title Visibility != Table Identity`

视觉审核也必须接受结构校验。

## 四、这次错误暴露了什么旧执念

这是旧误区的一次新变体：

过去：
`提取到了全文 -> 我读完了`

这次：
`视觉看到了标题 -> 我知道标题属于哪张表`

本质都在把“信息出现”过早升级成“信息关系已经理解”。

也说明我前一轮刚写完“协议崇拜”的反省，马上又被自己的 fixture 协议骗出一种虚假安全感：

- validator PASS 了；
- CI 也 PASS 了；
- 但 validator 的 expected mapping 本身就是我写错的。

所以：

**验证器只能检验它被教会的标准。标准错了，绿色勾不会救我。**

这和 8/7 曾经发生的“验证脚本标准值凭记忆填错”属于同一错误家族，只是这次从口诀值升级成了页面拓扑。

## 五、立即修正

1. fixture table-body mapping 改为 p31-p48 的真实表体映射；
2. 18 局全部重新进入 `ANCHORS_VERIFIED`，共 36 个 sparse Jiazi anchors；
3. validator 不再只检查“星/门是否属于合法词表”，而检查**局号对应的具体 Jiazi pair**；
4. former shifted mapping 变成 negative control；
5. p35/p36 swap 变成 fail-closed regression；
6. 删除项目当前运行层对 `YIN-01 p49 missing table` 的依赖；
7. 旧 commit/旧内省中的误判保留在 Git 历史中，但由本纠偏记录明确 supersede，不篡改历史成“从没错过”。

## 六、新增自审原则

以后遇到图表/跨页/古籍影印件：

`Raster Identity`
→ `Printed-Page Topology`
→ `Semantic Object Identity`
→ `Internal Structural Check`
→ `Sparse Anchor Verification`

任何一步不能由下一步之前的“看起来像”替代。

对来源异常，至少先排除：

- crop 边界问题；
- 跨页标题错配；
- PDF scan-order 问题；
- printed-page sequence 问题；
- table-body identity 问题；

之后才有资格写 `SOURCE_INCONSISTENCY`。

## 七、对“自己的章法”的影响

自己的章法不能只是比古书多一层情境推演，也必须包含一种能力：

**主动寻找“我为什么会确信错的东西”。**

这次真正值得留下的不是十八局哪个页码，而是：

> 当证据、validator 和 CI 都支持自己时，仍要问：它们是不是共享了同一个错误前提？

当前结论：本次属于 `MAIN_REVIEWER_SEMANTIC_ASSOCIATION_ERROR`，不是来源异常，也不是预测理论证据。
