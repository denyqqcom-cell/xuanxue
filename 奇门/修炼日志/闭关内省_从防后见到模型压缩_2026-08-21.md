## 一、已经真正修掉一部分的旧执念

### 1. “读过 = 学会 = 正确”已经被拆开

过去最顽固的问题是完成度膨胀：全文提取、结构地图、案例复盘，都曾被我提前写成“100%掌握”。现在 K2 强制把 Reading Credit、Atomic Evidence、Book Distillate、Source Fidelity、Empirical Support 分开，梁书 57/57 也必须逐页视觉核验后才记 COMPLETE。

这是真进步，但它只是把“我有没有认真读书”管住了，不等于把“书里的方法有没有用”解决了。

### 2. “书说了，所以可信”已经被拆开

现在明确：

`SOURCE != INFERENCE != EMPIRICAL_SUPPORT != CONTAMINATION`

以及：

`Source Fidelity != Lookup Determinism != Applicability != Empirical Support`

梁书十八局就给了一个很具体的提醒：p49 可以看到“陰遁一局圖”的标题，但看不到预期主表。标题正确不等于内容存在；内容存在不等于单元格已核验；单元格核验不等于代码正确；代码正确更不等于预测有效。

这说明“拆层”不是形式主义，本身能阻止我自动补全想当然的内容。

### 3. “错一次就发明一条万能规则”已经被压住

2026-06-15 的市场 miss 曾让我迅速推导出固定优先级、空亡新定义、凶格计分、新闻前置等补丁。现在这些都已降级或退出运行层。

真正的修正不是找到一个更漂亮的补丁，而是承认：**单次失败没有资格决定全局结构。**

## 二、这轮新发现：旧执念正在换壳复发

### M1. 从“规则崇拜”滑向“协议崇拜”

以前我容易觉得：规则越多，断得越准。

现在有另一种风险：觉得 freeze 字段越多、validator 越严、CI 越绿，方法就越成熟。

这是同一个执念换了工程化外衣。

`runtime contract PASS` 只能说明旧漏洞没从这个入口重新进来；`source fixture PASS` 只能说明来源复刻可审计；它们不能证明解释层更聪明，更不能证明预测优于基线。

**修正：**以后评价方法进步，不能只看 Gate 数量，而要看：

- 是否减少了真正的反馈后自由度；
- 是否提高不同分析者之间的可复现性；
- 是否改善校准；
- 是否在 clean prospective data 中优于 baseline / negative controls；
- 是否能删掉变量和例外，而不是只增加字段。

### M2. “限制自由度”本身可能过拟合成僵化

v0.2-alpha 把创新重点放在“先限制怎样解释”。这是当前比“不断扩象意词典”更可辩护的方向。

但如果我把每次遇到的分歧都变成一个永久必填字段，模型会越来越重：setup、calibration、seasonal alignment、time boundary、time family、layout、deity、star state、door state……

这些字段目前有合理来源，但未来不能因为“曾经发现过冲突”就永远保留。

**修正：约束也必须接受消融。**如果一个字段长期不改变结论、不改善区分力，或者两个字段高度耦合，应允许合并、降级或删除。

渐进迭代不只是“规则可删”，还应包括“协议字段可删”。

### M3. `CONTEXT_REQUIRED` 可能变成新的逃生门

过去的逃生方式是结果后换用神、换格局。

未来更隐蔽的逃生方式可能是：凡遇冲突就写 `CONTEXT_REQUIRED`，于是永远不犯错，也永远不真正做选择。

`CONTEXT_REQUIRED` 的本意是诚实标记未解决上下文，不应成为“无法被证伪”的永久状态。

**修正：**未解决项必须进入 ambiguity debt；要么在明确期限/实验里拆成 A/B，要么从当前可评分模型移除。不能无限累积。

### M4. “多分支”仍可能覆盖所有结果

我已经认识到单一叙事会后见，所以引入 competing branches。

但如果一个问题永远保留：

- 会发生；
- 会延迟发生；
- 不会发生；
- 暂时看不出；

那么形式上虽然“预注册了多分支”，实质上仍然覆盖了几乎所有未来。

这只是把后见自由度从“结果后选故事”搬到了“结果前列满故事”。

**修正：Branch Discrimination Gate**：

- 分支必须有限；
- 分支之间要有可区分观察；
- 每条必须写失败条件；
- 主分支必须在反馈前选定；
- 若使用概率/权重，必须反馈前冻结；
- 不能用“任一分支命中”来给整个模型记 HIT。

### M5. Reality Baseline 也可能污染方法-only

我过去犯过“完全不看现实”与“先看新闻再归因奇门”两个极端。

现在的 Reality Baseline 仍有边界风险：确认对象、时间、地点、公开定义属于必要事实；但如果 baseline 已包含高度预测性的新闻、赔率、天气预报、市场期货等，那么所谓 method-only 已经被污染。

**修正：Baseline Firewall**：

Reality Baseline 分成：

- `NEUTRAL_SETUP_FACTS`：识别对象/时间/地点/可评分目标所必需；
- `PREDICTIVE_AUXILIARY_FACTS`：本身对结果有预测力，必须走 auxiliary ablation 或标 PRE_EXPOSED。

不能因为信息是真实的，就自动把它归入“基础事实”。

### M6. 我可能沉迷“纠错工程”，却推迟真正的前瞻学习

这一阶段大量时间花在：schema、validator、runtime contract、source fixture、provenance、状态迁移。

这些工作必要，因为旧知识库确实存在严重污染和实现漂移。

但如果继续无限清债而迟迟不进入 clean unknown-outcome trials，我会得到一个越来越漂亮的研究框架，却没有新的现实检验。

这也是一种逃避失败：**只做不会输的工程题，不做会真正暴露模型能力的预测题。**

**修正：**完成必要的 implementation integrity 后，应把研究重心逐步移向 prospective trials。新书阅读、runtime 清债和前瞻测试必须形成比例，而不是一边无限增长。

### M7. “多书一致”容易被我重新包装成“高置信度”

现在已经知道多书一致只能增加 source consensus。但未来在 lineage review 时仍可能出现诱惑：三本、五本、十本都这么说，于是潜意识里把它当“现实规律”。

**修正：**多书一致只回答“传统内部共识多大”，不回答“现实命中率多高”。若没有独立结果数据，不跨层升级。

### M8. “自己的理论”不能变成又一本我自己写的圣经

用户要求最终走出自己的章法。这里最危险的误读，是把“原创”理解成“必须发明一套完整体系并维护它”。

真正属于自己的理论，不一定规则更多；可能反而更少、更清楚、更愿意承认不知道。

如果未来数据证明：某些传统象意没有增量、某些 context key 没用、某些关系链只是叙事美感，那么自己的理论应该敢于删掉它们。

**原创的标志不是和古书不一样，而是有自己的可证伪结构。**

## 三、当前理论的第二次收缩：从“约束解释”走向“约束 + 压缩”

当前最值得继续发展的不是新口诀，而是一个两层目标：

### 第一层：Constrain

反馈前固定会影响模型输出的重要选择，防止 hindsight rescue。

### 第二层：Compress

在保证可复现与区分力的前提下，主动寻找最小充分模型：

- 能否少一个 context key？
- 能否少一层固定优先级？
- 能否少一半 eligible features？
- 能否少一条 competing branch？
- 能否删掉没有增量的传统象意？
- 能否在更简单模型下保持或改善 prospective calibration？

因此新的创新方向暂记为：

`Constrained Situational Inference -> Discriminative Branching -> Prospective Audit -> Model Compression`

不是 v1.0 定论，只是 v0.2 系列的内省增量。

## 四、以后解盘必须多问的四个问题

在“这个象是什么意思”之前，先问：

1. **如果我不知道结果，我现在会不会仍然选这个解释？**
2. **这个解释有没有一个明确会失败的结果？**
3. **如果删掉这个象/字段/格局，结论还会不会一样？**
4. **我是在利用盘面信息，还是在利用现实已知线索后再让盘面配合故事？**

这四问比再背二十条断语更重要。

## 五、对下一阶段的纪律

1. 不因为当前 CI 全绿就宣布方法成熟。
2. 不因为 17 局 fixture 对上就宣布梁书体系有效。
3. YIN-01/p49 来源异常继续保留，不按顺序补造。
4. implementation check 必须包含 wrong-bureau / permuted negative controls。
5. Prospective trial 必须有可失败的主结论，不能靠备选分支全覆盖。
6. Reality Baseline 必须区分 neutral setup 与 predictive auxiliary。
7. 每增加一个冻结字段，都要问未来什么证据可以把它删掉。
8. 每读完一本书，不只问“新增了什么”，还要问“我能删掉什么”。
9. 任何理论版本都不享有保护期；只保护可追溯过程，不保护结论本身。
