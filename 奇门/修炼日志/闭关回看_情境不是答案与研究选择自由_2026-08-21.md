# 闭关回看：情境不是答案，与研究选择自由 — 2026-08-21

性质：SELF-DIALOGUE / METHOD RETROSPECTIVE / NO READING CREDIT / NO EMPIRICAL CREDIT

这次不急着再添一个 Gate，也不因为又想到一点东西就升理论版本。

我想先把旧笔记摊开，问自己几个不太舒服的问题。

---

## 一、先问自己：我是真的摆脱“背书式解盘”了吗？

8 月 7 日的《情境推演法 v0.1》抓到了一个真问题：

`符号 -> 通用断语 -> 现实结论`

太机械。

当时我提出：

`符号 × 具体情境 × 能量状态 -> 具体判断`

这个方向是对的。

但今天回头再读，我看到一句当时完全没觉得危险的话：

> 书本给我符号，情境给我答案。

现在看，这句话本身就是一个新的后见偏差入口。

**情境不能给我答案。**

如果情境已经负责“给答案”，那么我只要知道足够多的现实背景，就总能从星门神里挑出一条贴合现实的叙事线。那不叫推演，只是把现实答案重新翻译成奇门语言。

更严格的说法应该是：

`书给候选 -> 情境限定角色与语义边界 -> 盘内关系形成可失败输出 -> 现实结果只负责事后评分`

所以现在要把“结合实际”重新校准：

- **结合情境**：为了知道谁是谁、什么变量在当前问题里有意义；
- **不是结合答案**：不能因为已经知道对象最近发生什么，就反过来挑最像的象意；
- **现实常理**可以进入实践决策，但若它本身具有预测力，验证时必须列入 `PREDICTIVE_AUXILIARY_FACTS`，不能把它的贡献算给奇门。

这不是退回背书式解盘，而是把情境从“自由解释器”降回“约束器”。

---

## 二、再问：v0.1 的“📖高可信、🧠冲突时以🧠为准”，是不是也有问题？

有，而且是两个方向同时有问题。

### 1. 📖 不应该天然高可信

书上准确写了什么，只能提高 `Source Fidelity`。

它不能自动提高：

- 现实真值；
- 当前情境适用性；
- 预测有效性。

这件事后来已经通过 K2 的 `SOURCE / INFERENCE / EMPIRICAL_SUPPORT / CONTAMINATION` 分层纠正。

### 2. 🧠 也不应该因为“更贴合情境”就自动压过📖

v0.1 当时写：

`📖与🧠冲突时，以🧠为准，但保留📖原文。`

现在看，这仍给了分析者过大的自由。

如果我的情境解释和来源规则冲突，正确动作不应该默认是“我更懂现实，所以听我的”，而应该先问：

- 是来源规则本就只适用于另一 method family？
- 是 Role Map 错了？
- 是来源内部有冲突？
- 是我在用结果已知的现实背景修故事？
- 还是这个来源规则本身真的应该被拒绝？

在反馈前无法区分时，应保留有限竞争分支、A/B 或 abstain，而不是让情境推断拥有无限 override 权。

所以现在的关系是：

`SOURCE != AUTHORITY`

同时：

`CONTEXT_INFERENCE != OVERRIDE_AUTHORITY`

两边都不能当圣旨。

## 三、再翻 6 月 15 日：为什么一次失败会让我一下子“悟出”那么多规则？

那天 A 股方向完全预测反了。

我随后马上总结：

- 开门/政策优先级高于值符死门；
- 马星是中性变化；
- 逢空是方向待定；
- 以后每次预测必须看至少三条宏观新闻。

当时这些话很有“反省后的清醒感”。

但今天看，它们混在了三个完全不同的层级：

1. **合理纠错**：马星不能仅凭名字预设方向；
2. **待检验假设**：某些市场问题中外部驱动可能压过盘内某些结构；
3. **污染性补丁**：为了避免再错，要求预测前主动阅读能直接提示市场方向的新闻，然后仍想评价奇门有没有预测到。

最危险的不是失败，而是失败后特别容易产生一个完整、顺畅、能安慰自己的因果故事。

所以现在坚持：

`Outcome -> Case Lesson -> Testable Hypothesis -> Prospective Discrimination -> Rule Update`

中间不能再跳级。

## 四、再翻 8 月 11 日：叙事连贯性是进步，还是另一种“讲得通”？

8 月 11 日吸收了“关系链”和“叙事连贯性”，这部分我仍然认为值得保留。

但当时又正式化了：

`同一盘面可以有多条合理叙事线，再选最贴合情境的一条。`

这句话如果没有冻结与判别条件，几乎就是 narrative rescue 的合法化。

因此今天要再划一条线：

**关系链是为了减少逐符号散乱，不是为了提高故事自由度。**

一条关系链只有在它能导致不同的未来观察时，才增加判别信息。

如果 A、B、C 三种叙事最后都能解释同一个结果，它们不是三种洞见，而是三个自由度。

所以：

`叙事连贯性` 只能做表达质量指标；

`可区分性 / calibration / failure condition` 才能做模型质量指标。

## 五、一个今天才更清楚的漏洞：冻结一局，不等于冻结研究者

这段时间已经把单 case 的自由度压得很细：

- method；
- setup；
- time boundary；
- Role Map；
- feature set；
- competing branches；
- timing；
- auxiliary policy。

但我忽略了一个更高层的问题：

**我可以在每个 case 内完全守规矩，却仍然通过“选择研究什么”来骗自己。**

例如：

- 只挑我觉得盘面容易解释的 unknown-outcome case；
- 只挑支持当前实现的 worked plate；
- 只去翻最可能证明我对的书页；
- 负对照只选最容易输给正确模型的扰动；
- 做到几个漂亮 PASS 后就停；
- 失败的 source comparison 因为“上下文不清”一直不进入总结；
- 某条旧规则一直没被测试，但因为存在得久就默认保留。

这些都不发生在单 case 内，因此现有 `Prediction Protocol Freeze` 抓不到。

我把它暂时拆成三个自由度：

### MODEL_DOF

单次模型内部能改变答案的选择。

当前主要由 FREEZE 管。

### SELECTION_DOF

研究者选择：

- 哪个 case；
- 哪本书；
- 哪几页；
- 哪个 worked plate；
- 哪种 negative control；
- 哪个指标。

### STOPPING_DOF

研究者选择：

- 做到几例停止；
- 何时宣布“足够支持”；
- 何时因为连续失败改题；
- 何时结束一个 source search。

如果只控制 MODEL_DOF，而 SELECTION_DOF / STOPPING_DOF 完全自由，仍然可以得到一套看起来非常漂亮的“持续进步史”。

## 六、怎么修，又不把自省变成新官僚体系？

我不想为此再增加十几个 registry 字段。

先做一个最小实验：**Attack Queue**。

原则只有几条：

1. 在不知道某个 source/test 会支持还是反对当前模型前，先登记为什么要查它；
2. 每个问题同时写“什么结果会让我缩窄/删除当前观点”；
3. PASS、FAIL、NO-OP 都保留；
4. matched comparison 在开始前写清样本数/时间窗/停止条件；
5. 不因为某本书已经读顺手，就无限从同一谱系找支持材料；
6. Attack Queue 是研究选择的便签，不是新的“完成率成绩表”。

如果这个做法本身没有减少 cherry-picking，就删除，不升级成 Gate。

---

## 七、还有一条必须补上的纪律：旧规则没有继承权

v0.1 当时强调“渐进迭代，不推翻已有体系”。

这个出发点是避免一天一个新理论，但后来我发现它会产生另一种偏差：

**Grandfathering / 遗产规则偏差。**

某条规则只因为：

- 我很早就学过；
- 写在旧知识库；
- 用过很多次；
- 曾经被标过✅；
- 已经被多个新框架“收编”；

就变得越来越难删除。

这和真正的渐进成长不是一回事。

渐进不代表旧东西永久保留；渐进指的是每次修改有证据链、有版本记录、不抹历史。

因此：

`历史存在时间 != 支持强度`

`被多个版本继承 != 被独立验证`

`旧规则没有默认生存权`

进入当前 operational model 的遗产规则必须重新回答：

- 它现在属于 SOURCE、INFERENCE 还是 EMPIRICAL_SUPPORT？
- 删除它会不会改变结果？
- 它是否在 shuffled / wrong-input control 中同样“有效”？
- 有没有更简单的变量已经覆盖它？

回答不了，就应该 `NARROW / RESEARCH_ONLY / MERGE / DELETE`，而不是因为“以前都这么用”继续存在。

## 八、今天对自己说的话

我发现自己过去有两种相反但同源的冲动。

一种是“书里写了，所以照着走”。

另一种是“书太死，所以情境可以灵活解释”。

前者把自由度交给书；后者把自由度全拿回自己手里。

真正难的是中间这条路：

**书不能替我判断，情境也不能替我猜答案。**

书给候选结构；

情境只把角色、对象、边界说明白；

关系推演必须在反馈前形成可失败的东西；

结果来了先认输赢，再谈为什么；

长期留下来的，不是最会解释的规则，而是删了以后真的会变差的规则。

这才更接近“把学到的揉碎，长出自己的东西”。

---

## 九、本轮决定

`KEEP`：v0.3-alpha 的 FRAME / FREEZE / RELATE / DISCRIMINATE / FALSIFY / COMPRESS 六步骨架。

`REVISE`：把“情境给答案”彻底改成“情境定角色与约束边界”。

`REVISE`：自由度审计从 case 内部扩大到 `MODEL_DOF / SELECTION_DOF / STOPPING_DOF`。

`DELETE`：旧规则因历史悠久而默认保留的隐性继承权。

`TEST`：先用轻量 Attack Queue 检查研究选择偏差，不新增 Prospective Registry 顶层 schema。

`NO-OP`：理论版本仍是 `反证情境压缩法 v0.3-alpha`；这次自省本身不够资格升 v0.4。

一句话留给下一次回头看：

> **情境不是答案，旧规则没有祖荫，研究者自己的选择也必须接受反证。**
