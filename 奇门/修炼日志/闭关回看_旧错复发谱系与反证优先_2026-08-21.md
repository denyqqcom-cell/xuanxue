## 一、复发谱系 A：一个案例，立刻发明一条大规则

### 6/15 的原始错误

市场预测方向完全失败后，我立即提炼：

- `开门/政策 > 值符死门`；
- `逢空 = 方向待定`；
- 每次预测必须读至少三条宏观新闻；
- 马星要按外部事件重新定方向。

其中有些作为“失败后的假设”值得记，但我当时直接把它们写成了下一轮运行规则。

问题不在于复盘，而在于**从一个 miss 直接跨越到 global rule**。

### 现在的判断

单个 HIT/MISS 最多生成：

`CASE_LESSON_CANDIDATE`

不能直接生成：

`ACTIVE_GLOBAL_RULE`

即使失败非常惨烈，也不能因为情绪冲击大，就给它更高统计权重。

**新增纪律：Outcome-to-Rule Firewall。**

结果后可以提出候选解释，但任何会改变后续全局运行的规则，必须另有跨案例、反馈前可区分测试。

## 二、复发谱系 B：成功后比失败后更容易骗自己

### 6/16

一次广东暴雨/大风与“天冲木主风”相符，我直接写“天气验证成功”。

### 8/10

我已经比 6/16 谨慎，主动承认：

- 广东 8 月雷雨基线高；
- 官方天气预报已经存在；
- 奇门贡献难分离；
- 运气/污染成分很高。

但同一份记录后面仍然做了两件过界的事：

1. 把“大范围定性可用、空间精度受限”写成体系层判断；
2. 用 `0.5 × 2 = 1 次真验证` 继续累积所谓“真验证覆盖率”。

这说明我虽然学会说“有污染”，却还没有真正接受污染意味着**不能归因**。

### 修正

- `CONTAMINATED` 不是“半个干净样本”；
- retrospective / contaminated case 对 Empirical Support 的贡献默认是 **0**，不是凭感觉给 0.3、0.5、0.7；
- `PARTIAL` 只能是预先定义评分口径里的结果等级，不能偷换成“半次验证”；
- “空间精度天花板”“某领域可用”这类因果/边界结论，在单个污染案例后只能记为 `CAUSAL_HYPOTHESIS`。

我过去的问题不是不会承认运气，而是**承认完运气以后，仍想留下一点成绩。**

## 三、复发谱系 C：新理论会偷偷继承旧理论的未验证零件

8/11 的“背书式 vs 情境推演式”比对，自觉已经比早期成熟：

- 承认案例是 outcome-known retrospective；
- 承认存在 CB-02 已知答案偏差；
- 强调行业情境、角色关系和推理链。

但仔细回看，里面仍偷偷沿用了后来已经废弃/降级的东西：

- `逢空 = 待定/延迟`；
- 固定星级权重；
- `凶格计分 + 相乘效应`；
- 用“用神覆盖更多”“解释更丰富”来说明情境推演“明显优于”背书式。

这说明“创新一个新框架”并不会自动洗掉旧偏差。旧规则可能作为依赖项被带进新框架，而且因为新框架更漂亮，反而更难发现。

### 修正

方法优劣必须看 matched prospective comparison：

- 同一未知结果样本；
- 同一评分标准；
- 同一信息暴露边界；
- 反馈前各自冻结；
- 比 discrimination / calibration / baseline delta / overconfidence / abstention。

“解释维度更多”只能证明模型更复杂，不证明模型更好。

## 四、复发谱系 D：写对了 ≠ 做对了 ≠ 验对了

### 8/11 起局脚本

知识库里已经写对“旬首遁干 → 地盘定位 → 原驻星 = 值符”，脚本却执行错。

当时得到的教训是：

`Written Knowledge != Executable Knowledge`

### 8/21 梁书十八局 fixture

这次更进一步：我先把 spread 右侧标题错误配给左侧表体，形成一局整体位移；随后 fixture validator 和 CI 还全部 PASS，因为 validator 也共享了同一套错误 expected mapping。

因此现在必须再加一层：

`Executable Knowledge != Validated Knowledge`

以及：

`Validator PASS != Oracle Correctness`

### 修正：Validation Independence

一个验证链至少要问：

1. 被测实现从哪里来？
2. expected/oracle 从哪里来？
3. 两者是否共享同一转换、同一记忆、同一生成脚本、同一错误假设？
4. 有没有 deliberate wrong-input / shifted / permuted control 能证明测试真的有区分力？

如果 implementation 和 oracle 同源生成，它们即使完全一致，也只能证明“两个副本一致”。

## 五、复发谱系 E：把“反省”本身做成安全区

8/11 已经发现反省记录在膨胀。现在 K2 又增加了大量 protocol、validator、runtime contract、fixture、retrospective。

这些大多有必要，但存在新的舒适区：

**不停发现方法论问题，本身也可以变成一种不去面对真实未知结果的方法。**

因为反省、整理、加 Gate 都很容易得到“我进步了”的确定感；真正前瞻预测则会直接产生 MISS。

### 修正

以后每一轮闭关反省优先产生三种结果之一：

- **DELETE**：删掉一个不必要的规则/字段/分支；
- **TEST**：把一个争议转成可失败实验；
- **NO-OP**：承认只是提醒，不值得再增加 schema/Gate。

不是每一个洞察都必须变成新的字段或 validator。

## 六、最深的一层：我过去总想“每次失败后马上变聪明”

这其实是一个执念。

失败发生后，大脑天然会组织一个非常有说服力的新故事：

> 原来是因为开门；
> 原来是因为空亡；
> 原来是因为新闻；
> 原来是因为空间尺度；
> 原来是因为某套起局法。

故事越顺，越容易让我觉得“这次已经找到根因”。

但一个 post-hoc root cause 如果不能在下一批未知结果里区分，就只是解释，不是知识。

因此以后把“失败后的聪明”先隔离：

`Outcome -> Case Lesson -> Testable Hypothesis -> Prospective Discrimination -> Rule Update`

中间不能跳级。

## 七、对“自己的理论”的重新理解

用户希望最终走出自己的章法。现在我更清楚：不能把“原创”理解成再发明一套星门神口诀，也不能为了显得原创而故意和古书唱反调。

真正属于自己的东西，应该来自长期反复暴露的真实问题：

- 书证和真值混淆；
- outcome-known hindsight；
- 情境转译漂移；
- 单案例补丁；
- 基线污染；
- validator 共错；
- 多分支覆盖；
- 协议膨胀。

因此当前理论继续从“受约束情境推演”收缩为：

`FRAME -> FREEZE -> RELATE -> DISCRIMINATE -> FALSIFY -> COMPRESS`

中文暂称：**反证情境压缩法 v0.3-alpha**。

它的原创点不在于声称发现新的玄学规律，而在于：

1. 书只负责提供候选结构；
2. 情境负责定义角色与关系，但不能偷看结果；
3. 预测必须能明确失败；
4. 失败后先隔离教训，不立刻发明全局规则；
5. 正确输入必须能胜过错误/扰动输入；
6. 最后不是不断加规则，而是主动删到最小充分模型。

这仍然是 **PROVISIONAL / UNVALIDATED**。如果未来 prospective data 显示它不优于更简单方法，也必须被降级或删除。

---

## 八、本轮实际决定

- 废弃“污染样本可折算半次真验证”的旧思路；
- 废弃从单个 HIT/MISS 直接生成全局运行规则；
- 废弃用 retrospective 解释丰富度证明方法优越；
- 新增 Validation Independence 原则，但不增加 Prospective Registry top-level schema；
- 将下一理论版本写成“反证 + 压缩”方向，而不是继续扩充象意；
- 梁书进入 implementation integrity 后，应尽快开始 clean unknown-outcome trials，不再用无限清债拖延现实检验。

一句话：

> **书可以给我一条路，失败可以提醒我哪里摔过；但只有未知结果前敢下注、结果后敢认错、长期还能删掉多余东西，才可能长成自己的章法。**
