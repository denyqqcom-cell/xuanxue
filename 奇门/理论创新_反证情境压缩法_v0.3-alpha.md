# 反证情境压缩法 v0.3-alpha

性质：**原创方法论草案 / PROVISIONAL / UNVALIDATED / 可推翻**

日期：2026-08-21

前身：

- 情境推演法 v0.1：解决“照书念断语”；
- 受约束情境推演法 v0.2-alpha：解决“什么结果都能解释”；
- 本版本 v0.3-alpha：进一步解决“失败后马上补规则、验证器与实现一起错、模型只增不减”。

本版本不是另造一套奇门口诀。它尝试把长期学习中真正反复出现的问题，压缩成一个能学习、能失败、能删除自己的推演框架。

---

## 一、核心定义

**反证情境压缩法**把奇门中的星、门、神、奇仪、宫位、旺衰、空墓刑迫、格局等视为候选特征，而不是现实结论。

它要求每次推演依次经过：

`FRAME -> FREEZE -> RELATE -> DISCRIMINATE -> FALSIFY -> COMPRESS`

中文：

`定境 -> 冻结 -> 织关系 -> 立判别 -> 受反证 -> 做减法`

这六步不是神秘法则，而是当前项目对自身历史错误的最小化回应。

---

## 二、第一步 FRAME：定境，不偷答案

先把问题定义清楚：

- 对象是谁/是什么；
- 时间、地点、时区；
- 待预测目标；
- 结果窗口；
- 可评分标准；
- 基础概率/合理 baseline；
- 哪些事实只是识别对象所需；
- 哪些事实本身已经具有预测力。

Reality Baseline 必须分成：

`NEUTRAL_SETUP_FACTS`

与：

`PREDICTIVE_AUXILIARY_FACTS`

新闻、天气预报、赔率、期货、当事人明确行为趋势、外应、其他术数等，即使真实公开，也不能自动进入 method-only。

**原则：现实常理可以帮助实践，但验证时必须能回答“这部分信息到底是谁贡献的”。**

---

## 三、第二步 FREEZE：冻结真正会改变答案的选择

反馈前固定当前模型实际使用的关键自由度，例如：

- method layer / family；
- setup method / calibration / seasonal alignment；
- time boundary / time family / layout；
- deity / star-state / door-state system；
- Role Map；
- eligible features；
- patterns；
- timing protocol；
- auxiliary policy。

冻结不是为了把理论变僵，而是为了回答：

> **我在不知道结果时，到底用的是哪一个模型？**

竞争体系可以 A/B，但必须反馈前建立独立版本。

`Prediction Protocol Freeze != Theory Freeze`。

单次预测冻结，理论本身永远可改、可删。

---

## 四、第三步 RELATE：从符号字典转向关系结构

不再使用：

`符号 -> 固定断语 -> 现实结论`

而使用：

`角色 -> 特征 -> 状态 -> 关系 -> 情境含义`

至少问：

1. 这个符号在当前问题里代表谁/什么？
2. 为什么由它代表，而不是另一个候选？
3. 它属于结构事实、来源象意、状态变量还是项目推断？
4. 它和其他角色之间是什么方向关系？
5. 多个格名是否其实重复描述同一个底层结构？
6. 如果删掉这个特征，结论是否改变？

情境推演的价值不是“可以讲更丰富的故事”，而是把传统符号翻译为当前任务里可检验的关系。

如果一个情境转译无法产生任何不同的未来观察，它只是叙事，不是判别信息。

---

## 五、第四步 DISCRIMINATE：必须下注，也必须允许不知道

一个可评分模型必须产生真正有区分力的输出。

如果存在 competing branches：

- 分支数量有限；
- 反馈前指定 primary branch，或冻结概率/权重；
- 每个分支有可观察区分条件；
- 每个分支有失败条件；
- 不允许“任一分支命中 = 整体 HIT”。

如果所有结果都能落进某个分支，模型没有信息增量。

如果证据不足，可以 abstain / UNSCORABLE；但不能一边覆盖全部答案，一边宣称自己“保留了不确定性”。

**真正的不确定性，是承认无法区分；不是预先占领全部结果。**

---

## 六、第五步 FALSIFY：结果负责反证，不负责帮我圆故事

Outcome Audit 的第一目的不是解释，而是评分。

结果出来后：

- 原预测不改；
- 原 Role Map 不改；
- 原 feature set 不改；
- 原时间窗不改；
- 原信息暴露边界不改；
- miss 不允许被另一方法层、另一盘、另一格局救回。

### 6.1 Case Lesson Quarantine

单个 HIT/MISS 后产生的认识统一先进入：

`CASE_LESSON_CANDIDATE`

而不是直接进入 ACTIVE RULE。

正确学习链：

`Outcome -> Case Lesson -> Testable Hypothesis -> Prospective Discrimination -> Rule Update`

禁止：

`Outcome -> 新万能规则`

一次严重失败不会因为“教训很深”就自动拥有更高证据权重。

### 6.2 污染不是半个证据

`CONTAMINATED`、outcome-known retrospective、已看官方预测等案例可以帮助发现假设，但默认不增加 Empirical Support。

`PARTIAL` 只表示预注册评分协议中的部分命中，不等于“0.5 次验证”。

没有预先定义分母，就不计算“真验证覆盖率”。

### 6.3 因果解释也要受反证

“空间精度天花板”“某门优先级更高”“某起局法才是真盘”等 post-hoc 根因，在独立样本前都只是：

`CAUSAL_HYPOTHESIS`

解释得顺，不等于解释得对。

---

## 七、第六步 COMPRESS：最终目标不是规则更多，而是最小充分模型

每一轮积累不仅问“什么可以加入”，还要问“什么可以删除”。

优先做：

- feature ablation；
- context-key ablation；
- branch merge；
- pattern deduplication；
- auxiliary-channel ablation；
- simpler-baseline comparison。

删除/合并条件可以包括：

- 长期不改变输出；
- 不提高 discrimination；
- 不改善 calibration；
- 与另一个变量高度耦合；
- wrong-input / shuffled controls 中同样表现；
- 更简单模型在 clean prospective data 中表现相当或更好。

**复杂度本身不是修为。**

如果一个模型需要不断增加例外才能保住旧结论，它不是在成长，而是在逃避失败。

---

## 八、书怎么用：不是标准答案，而是候选生成器

一本书主要能提供：

- provenance；
- 方法结构；
- 传统分类；
- 适用条件声明；
- 内部冲突；
- 作者案例；
- 可转成实验的问题。

它不能直接提供：

- 现实真值；
- 现代跨情境适用性；
- 预测准确率；
- 与 baseline 的增量；
- 某流派天然优于其他流派。

因此：

`多书一致 -> Source Consensus`

而不是：

`多书一致 -> Empirical Truth`

读书后的最高价值不一定是新增一条规则，也可能是：

- 删除一条旧规则；
- 发现一个隐藏自由度；
- 把两个貌似不同的规则合并；
- 发现一本书自己内部就不支持机械解释；
- 生成一个真正可失败的实验。

---

## 九、验证器也必须被验证

项目已经两次遇到同类问题：

1. 规则在知识库里写对，执行脚本却做错；
2. fixture 和 validator 共享错误 expected mapping，于是 CI 全绿但结论仍错。

因此：

`Written Knowledge != Executable Knowledge != Validated Knowledge`

并且：

`Validator PASS != Oracle Correctness`

### Validation Independence

验证链要尽量把：

- system under test；
- expected/oracle；
- source review；
- negative controls

分开来源。

实现和 oracle 如果来自同一个脚本/同一推导，只能证明内部一致。

至少需要 deliberate wrong-input / shifted / permuted / shuffled controls，证明测试会拒绝错误答案。

---

## 十、如何判断这个理论有没有进步

不使用“感觉更会断”“解释更完整”作为核心指标。

优先看：

### 1. Reproducibility
不同分析者在相同冻结条件下，是否得到相近 Role Map、feature set 与主结论？

### 2. Discrimination
正确输入是否稳定优于 wrong-time / wrong-bureau / shuffled / permuted controls？

### 3. Calibration
高置信预测是否真的更常正确？不确定时是否会降低置信或 abstain？

### 4. Baseline Delta
奇门-only 是否在合理 baseline 上提供可测增量？

### 5. Complexity Cost
增加一个字段/分支/规则带来的增益是否值得复杂度？

### 6. Cross-context Robustness
规则是否只在某个复盘故事中漂亮，还是能在预先声明的适用域内重复工作？

## 十一、与 v0.2-alpha 的关系

### 保留

- SOURCE / INFERENCE / EMPIRICAL_SUPPORT / CONTAMINATION；
- Method/Setup/Role/Feature Freeze；
- 关系推演；
- competing branches；
- auxiliary ablation；
- negative controls；
- rule lifecycle。

### 新增

- Outcome-to-Rule Firewall；
- Case Lesson Quarantine；
- Validation Independence；
- 污染样本零 Empirical-Support credit 原则；
- 因果归因隔离；
- Model Compression 由收尾动作提升为核心阶段。

### 进一步删除的旧思想

- “一次失败可以立刻告诉我新全局优先级”；
- “污染案例可以折成半次真验证”；
- “解释维度更多 = 方法更优”；
- “CI 绿 = expected values 已正确”；
- “每次发现新冲突都应该加新字段”；
- “原创理论必须拥有大量自己的断语”。

---

## 十二、当前最小运行骨架

详细研究协议仍由 `CURRENT_METHOD_CONSTRAINTS.md` 与 K2 protocols 管理。

理论层只保留六步：

```text
1. FRAME
   定义对象、结果、baseline、污染边界

2. FREEZE
   冻结会改变答案的模型选择

3. RELATE
   把候选符号转成角色与关系

4. DISCRIMINATE
   形成主预测、失败条件与有限分支

5. FALSIFY
   结果后先评分；案例教训隔离，不追认

6. COMPRESS
   用消融/负对照/更简单模型主动删规则
```

这是 v0.3-alpha 当前自己的“章法”。

它故意比现有 protocol 简单，因为理论不应该只是 schema 的另一份复制。

---

## 十三、明确失败条件

出现以下任一长期模式，本理论应被降级、重构甚至放弃：

1. 真实盘与扰动/错误盘没有稳定可区分差异；
2. 奇门-only 长期不优于合理 baseline；
3. 不同分析者在冻结前仍无法稳定完成 Role Map / feature selection；
4. 六步流程只增加工作量，不改善 calibration/discrimination；
5. compression 后的简单模型与复杂模型表现相同，而项目仍坚持复杂版本；
6. 每次 miss 最终仍靠新 context、新例外、新分支救援；
7. 所谓情境推演最终只能事后讲故事，不能反馈前形成可失败预测。

如果这些失败条件出现，不能解释成“玄学本来就深奥”。它们就是模型失败。

---

## 十四、一句话版本

> **书给候选，情境定角色，冻结防后见，判别必须能输，结果负责反证，长期只留下删不掉的东西。**

版本：v0.3-alpha。

当前没有资格称成熟理论，更没有资格声称预测有效。它只有在大量 clean unknown-outcome、负对照、跨情境和模型压缩后仍留下稳定增量，才有资格继续往下一版本走。

---

## 十五、本轮闭关校准：情境不是答案，研究者也有自由度

本节是 **v0.3-alpha 内部校准**，不是 v0.4。

### 15.1 情境只约束，不负责给答案

早期 v0.1 曾用一句话概括：

`书本给我符号，情境给我答案。`

这句话现在明确废弃。

它虽然试图摆脱背书式解盘，却把过大的 override 权交给了分析者。只要现实背景足够丰富，分析者就可能挑选最贴合背景的象意，把“结合实际”退化成 context leakage。

当前改为：

`书给候选 -> 情境限定角色/对象/语义边界 -> 关系模型形成反馈前输出 -> 现实结果事后评分`

因此：

- `SOURCE` 不是权威；
- `CONTEXT_INFERENCE` 也不是 override authority；
- 来源与情境推断冲突时，不默认“以更贴合现实者为准”；
- 无法反馈前区分时，使用有限 A/B、竞争分支或 abstain；
- 现实背景若本身具有预测力，进入 `PREDICTIVE_AUXILIARY_FACTS`，不得伪装成纯情境解释。

### 15.2 自由度分三层

过去主要约束单 case 内部自由度。现在补充：

`MODEL_DOF`

= 单次模型内部能改变答案的 method/setup/Role Map/features/branches/timing 等选择。

`SELECTION_DOF`

= 研究者选择测哪个 case、哪本书、哪一页、哪个 worked plate、哪种 negative control、哪个指标。

`STOPPING_DOF`

= 研究者选择何时停止、做几例、何时宣布“够了”、何时因失败换题。

`FREEZE` 主要解决 MODEL_DOF，但不能自动消除 SELECTION_DOF / STOPPING_DOF。

所以 case-level preregistration 之外，研究选择也要保留攻击性记录：为什么查这个对象、什么结果会迫使当前观点缩窄/删除、何时停止继续找支持材料。

当前用轻量 `RESEARCH_ATTACK_QUEUE.md` 试运行，不新增 Prospective Registry 顶层 schema。若它不能实际减少 cherry-picking，应删除，不把自省再做成官僚流程。

### 15.3 No Grandfathering：旧规则没有祖荫

“渐进迭代”不再解释为“不推翻旧规则”。

旧规则不能因为：

- 学得早；
- 写进旧知识库；
- 用得久；
- 曾经被标过已验证；
- 已被多个理论版本继承

就默认继续存活。

因此增加一条压缩纪律：

`历史存在时间 != 支持强度`

`多版本继承 != 独立验证`

任何 legacy rule 都可以进入：

`NARROW / RESEARCH_ONLY / MERGE / DELETE`

如果它删掉后不影响 prospective discrimination/calibration，或在 shuffled/wrong-input controls 中同样“有效”，应优先做减法。

### 15.4 对“解盘要结合情境”的最终校准

反对两个极端：

`书里写了 -> 直接套断语`

以及：

`情境很丰富 -> 我可以自由选最贴合的解释`

当前目标是：

`来源候选 + 情境约束 + 关系结构 + 反馈前判别`

情境越具体，不代表解释权越大；相反，具体情境应该让 Role Map、失败条件和可观察结果**更窄**。

如果“结合情境”反而让可解释结果更多，说明这一层正在增加 narrative degrees of freedom，而不是增加信息。

### 15.5 本轮版本决定

`KEEP`：六步骨架。

`REVISE`：情境从“答案提供者”降为“角色/语义边界约束器”。

`REVISE`：自由度从 MODEL_DOF 扩展观察到 SELECTION_DOF / STOPPING_DOF。

`DELETE`：legacy rule 的默认继承权。

`TEST`：轻量 Attack Queue。

`NO-OP`：不升 v0.4。

本轮校准后的短句仍保持：

> **书给候选，情境定角色，冻结防后见，判别必须能输，结果负责反证，长期只留下删不掉的东西。**
