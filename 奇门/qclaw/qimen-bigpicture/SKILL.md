# 大局特征：Feature Map 版

> **上位约束**：`奇门/CURRENT_METHOD_CONSTRAINTS.md`、`qimen-overview`。
>
> “先看大局”可以帮助发现盘面结构，但“大局”不是一个能够压过全部其他信息的万能裁决层。

## 一、伏吟 / 反吟：先识别结构

### 1.1 伏吟

传统奇门常把九星、八门回到本宫/原位的状态称为伏吟，并区分：

- 九星伏吟；
- 八门伏吟；
- 星门俱伏吟。

不同盘式对“本宫/原位”的技术定义必须按所选 layout 确认。

### 1.2 反吟

传统资料常把九星、八门落到相对冲宫称为反吟，并区分：

- 九星反吟；
- 八门反吟；
- 星门俱反吟。

仍须先确认盘式与对宫规则，不能只凭某个排盘软件标签。

---

## 二、传统语义：保留 SOURCE，不自动裁决

旧资料常把伏吟/反吟解释为：

| 结构 | 常见 SOURCE 关键词 |
|---|---|
| 伏吟 | 静、慢、反复少、停滞、守、利主 |
| 反吟 | 动、快、往返、反复、变更、利客 |

这些可以生成情境假设，但不能直接写成：

- 伏吟 = 一定失败/一定守成；
- 反吟 = 一定主动出击；
- 星门俱伏吟 = 自动“极凶”；
- 反吟婚姻 = 必离；
- 反吟久病 = 必死。

尤其婚姻、生死、疾病等旧断语只属于历史 SOURCE，不得直接作为现实高风险判断。

### 2.1 情境转译问题

看到伏吟/反吟至少问：

1. 当前任务需要稳定还是变化？
2. “慢/反复/往返”是否可观察、可区分？
3. 这个 feature 在本 Method Family 是主层还是辅助层？
4. 是否有更直接的 Role 关系与它冲突？
5. 什么结果会证明这次伏/反吟解释不成立？

---

## 三、天显时格：保留为来源规则，不作万能例外

部分《奇门遁甲预测学》资料把六甲旬首值班之时称“天显时格”，常列：

- 甲己日甲子时；
- 乙庚日甲申时；
- 丙辛日甲午时；
- 丁壬日甲辰时；
- 戊癸日甲寅时。

历史来源进一步主张此时虽呈伏吟却有特殊吉义。

当前状态：`SOURCE RULE / CONTEXT_REQUIRED`。

不得使用：

`伏吟不符合预期 -> 发现天显时格 -> 自动反转为吉`

若本次方法族允许天显时格作为例外条件，它必须在反馈前进入 Eligible Feature Set，并提前说明它怎样修改伏吟解释。

---

## 四、日干 / 时干关系：先看 Role Map

许多现代体系使用：

- 日干 = 求测者；
- 时干 = 所问事件。

这是常见 Role Map，但不是所有方法的唯一取法。

只有 Role Map 已冻结为上述模型时，日时宫之间的生克才进入解释。

旧版机械规则如：

- 日干克时干 = 主动掌控/吉；
- 时干克日干 = 压力/凶；
- 时干生日干 = 得助；

现统一降级为 SOURCE/INFERENCE 候选。生克是关系，不自动等于价值判断；详见 `qimen-shengke`。

---

## 五、时间参数：结构信息可以先标，权重不能先定

常见需要记录：

- 年干/年支；
- 月干/月支（月令）；
- 日干支；
- 时干支；
- 日旬空；
- 时旬空；
- 节气与局数来源；
- 马星等本方法需要的结构。

“必须标出来”与“必须进入最终结论”不同。

哪些参数属于 Eligible Feature Set，由当前 Method Family 在反馈前决定。

## 六、内外盘：校正版与边界

当前项目采用：

| 盘别 | 阳遁 | 阴遁 |
|---|---|---|
| 内盘 | **1、8、3、4** | **9、2、7、6** |
| 外盘 | **9、2、7、6** | **1、8、3、4** |

这与旧项目 2026-06-08 的原典校正一致。

历史错误 `阳遁内=1、3、4、9` 已在 overview / yingqi / basics 等运行文件中清理。

传统常把：

- 内盘 → 近、快、小、少；
- 外盘 → 远、慢、大、多。

当前只保留为 SOURCE/CANDIDATE。不能把“内外盘”直接转成固定天数、金额或距离；应期需进入 `qimen-yingqi` 冻结方法后测试。

---

## 七、主客动静不是“大局自动建议器”

旧资料会把：

- 伏吟 → 利主/宜静；
- 反吟 → 利客/宜动；
- 天地盘生克 → 主客；
- 前五/后五天干组 → 先动/后动；
- 急从神/缓从门 → 行动方向；

合并成一张行动表。

这会产生多个主客系统同时争夺解释权。

当前规定：

1. 先选择 Method Family；
2. 只启用该体系预注册的主客模型；
3. 其他主客规则列 OUT，不参与结果后救援；
4. 若要比较两个模型，冻结 A/B 两个预测。

详见 `qimen-shengke`。

## 八、旧“大局综合表”的降级

旧版：

| 格局 | 旧固定建议 |
|---|---|
| 伏吟 | 守成 |
| 反吟 | 出击 |
| 天显时格 | 先守后攻 |
| 正常局 | 看干支 |

这张表现已 **DEPRECATED AS ACTION RULE**。

原因：它把传统特征直接翻译成行为处方，没有先问目标、角色、成本、现实约束和竞争证据。

可以保留“伏吟偏静、反吟偏动”作为假设生成器，但行动建议必须由具体问题推演。

## 九、伏吟/反吟的高风险旧断语

历史来源中存在：

- “蓬+蓬、死+死、辛+辛，多遭盗贼、破财、死伤人口”；
- “反吟婚姻破裂”；
- “久病逢反吟则死”；
- “求财反吟劳而无功”等。

当前处理：

`SOURCE RECORD ≠ OPERATIONAL FACT`

这些断语可用于研究古法怎样组织象意、形成 Atomic Evidence 或冲突候选，但不能直接输出为现实预测，尤其不能用于生死、疾病、犯罪等高风险结论。

---

## 十、大局不是固定全局优先级

`QM-SRC-0016` 的蒸馏已迫使项目放弃跨场景固定信息层优先级。

所以：

- 静态/状态型问题可能把大局 feature 作为辅助；
- 动态问题可能更重主客、方位和天地盘关系；
- 九宫拟象可能更重空间映射；
- 应期问题又有自己的 timing features。

不得因为本技能名字叫“bigpicture”，就自动让伏吟/反吟压过 Role Map 和方法族。

## 十二、本轮对旧技能的纠偏

1. 伏吟/反吟从“行动命令”降为结构 feature；
2. “星门俱伏吟极凶”等传统标签不再自动裁决；
3. 天显时格不再作为反馈后反转伏吟的万能例外；
4. 日干/时干生克必须服从已冻结 Role Map；
5. 内外盘仅保留结构 + 待验证快慢语义；
6. 删除婚姻、生死、疾病等直接高风险预测的运行资格；
7. 多套主客模型不能混用；
8. “看大局”不等于恢复一个新的固定全局优先级。
