# 生克与主客：关系推演版

> **上位约束**：`奇门/CURRENT_METHOD_CONSTRAINTS.md`、`qimen-overview`。
>
> 核心原则：**生克描述关系，不自动决定吉凶。** 谁生谁、谁克谁必须先绑定 Role Map 与所问目标。

## 一、先纠正旧版的基础五行错误

旧版曾写出一个错误的“相生递进”：

`坎1水 → 坤2土 → 震3木 → 巽4木 → 中5土 → 乾6金 → 兑7金 → 艮8土 → 离9火`

这只是九宫数字顺序，**不是五行相生链**。

正确的基础五行结构是：

- 相生：`木 → 火 → 土 → 金 → 水 → 木`
- 相克：`木克土、土克水、水克火、火克金、金克木`

旧版宫间表还曾把“离火克艮土”“坎水克坤/艮”等写进关系表，这同样是基础五行错误。现全部撤销。

## 三、生克不等于吉凶

旧版常写：

- 用神生对方=吉；
- 用神克对方=有利；
- 对方克用神=凶；
- 比和=中平。

这会把关系方向机械翻成价值判断。

当前必须先问：

1. 两宫分别代表谁/什么？
2. 目标是合作、竞争、控制、获得、摆脱、治疗、保护还是其他？
3. “生”在当前关系中是支持还是消耗？
4. “克”是压制风险、控制资源，还是遭受冲突？
5. 哪一方的旺衰/状态只是强度 feature，哪一方决定目标？

例如同样是“我生对方”：

- 在合作关系里可能表示投入支持；
- 在求财问题里可能表示资本向外消耗；
- 在治疗类传统象里又可能有完全不同解释。

所以不允许从五行箭头一步跳成“吉/凶”。

## 四、门宫关系

传统常分：

- 门克宫（迫）；
- 宫克门（制）；
- 门生宫；
- 宫生门；
- 门宫比和。

结构可直接计算，但旧版“迫=大凶、门生宫=吉、宫生门=吉但付出”等固定语义现已降级。

实际推演：

```text
门在本题的 Role
+ 宫在本题的 Role / 环境含义
+ 生克方向
+ 状态强弱
+ 相反信号
→ contextual inference
```

详见 `qimen-sihai`。

## 五、天地盘主客：保留为方法族规则

部分《奇门遁甲应用学》类资料把：

- 地盘视为主/守/静；
- 天盘视为客/攻/动；

并进一步用主克客、客克主、客生主、主生客等判断主客策略。

当前状态：`METHOD-FAMILY-SPECIFIC SOURCE RULE`。

只有本次 Method Family 预先选择这一主客模型时才执行；不能与其他“值符/天乙”“日干/时干”“前五/后五天干”等主客系统随意叠加。

### 5.1 若选择天地盘主客模型

只先记录关系：

| 结构 | 传统命名候选 |
|---|---|
| 地盘克天盘 | 主克客 |
| 天盘克地盘 | 客克主 |
| 天盘生地盘 | 客生主 |
| 地盘生天盘 | 主生客 |
| 同五行 | 比和 |

传统策略解释须标 SOURCE，并在具体任务中情境转译；不自动输出“应该进攻/必须守成”。

## 六、旧“前五/后五天干=五阳/五阴”术语纠偏

旧技能依据善天道材料写：

- 甲、乙、丙、丁、戊 = “五阳干”，利客先动；
- 己、庚、辛、壬、癸 = “五阴干”，利主后动。

这里存在**术语混淆风险**。

按通常天干阴阳属性：

- 阳干：甲、丙、戊、庚、壬；
- 阴干：乙、丁、己、辛、癸。

因此善天道“前五/后五”的主客分组，不应在项目中继续无注释地叫“天干阴阳分类”。

当前统一写成：

- `SHANTIandao_FIRST_FIVE_GROUP = 甲乙丙丁戊`
- `SHANTIandao_LAST_FIVE_GROUP = 己庚辛壬癸`

并标记为该体系的**主客分组规则**，而不是基础天干阴阳事实。

若后续核对原书发现作者本身就明确使用“五阳/五阴”这个特殊术语，应忠实记录原文术语，同时保留本项目的 `TERMINOLOGY_CONFLICT` 注释，避免和基础阴阳属性混为一谈。

## 七、伏吟 / 反吟与主客

传统来源常把：

- 伏吟 → 静、慢、利主；
- 反吟 → 动、快、利客。

当前只作为 SOURCE/CANDIDATE。

必须结合：

- 星伏、门伏还是俱伏；
- 问题本身需要静还是动；
- 方法族是否真正使用主客；
- 现实目标是保持还是改变。

“慢”不自动等于坏，“快”不自动等于好。

---

## 八、急从神 / 缓从门

善天道资料提出“急则从神、缓则从门”。

当前把它视为一种**信息选择器**，不是所有奇门的基础公理。

若选择使用：

1. 预测前定义什么叫“急”、什么叫“缓”；
2. 冻结本题归类；
3. 急事使用该体系规定的信息层；
4. 缓事使用该体系规定的信息层；
5. 结果后不得因不符而把急切成缓或缓切成急。

---

## 九、旺衰只作为关系强度候选

传统体系会用旺、相、休、囚、死或九星旺衰修正关系强弱。

当前不接受：

- 旺=必胜；
- 衰=必败；
- 旺克衰=一定有效；
- 休囚克旺=一定反伤；
- 旺相“全额”、休囚“减半”。

更合适的工作语言：

`关系方向 + 状态 feature + 方法族解释 + 竞争证据`

如果要做权重模型，必须从数据中校准，不靠形容词直接定系数。

---

## 十、静态 / 动态方法差异

历史《应用学》资料本身已提示：静态预测和动态预测对生克、空间、天地盘主客的重视程度不同。

这正是当前 `Method-Family-Specific Priority` 的来源之一。

因此：

- 静态问题不必因为盘上存在天地盘生克就强行升为主证据；
- 动态/行动问题也不能只查静态吉凶词典；
- 方法族必须在反馈前冻结。

## 十二、红线

- 不再把宫位数字顺序当五行相生链；
- 不再出现“火克艮土”“水克坤土”之类基础五行错误；
- 不把生=吉、克=凶；
- 不把善天道前五/后五分组误写成基础天干阴阳；
- 不把伏吟/反吟直接变成行动命令；
- 不把不同主客模型混用后再挑有利结论；
- 不用未经校准的旺衰系数；
- 不在结果后切换急/缓分类。
