## 1. 第一处旧误区：把 TEXT 提取叫成“精读”

旧笔记开头已经写明：

`提取自 _txt/善天道精华.txt、善天道讲义.txt、善天道高级班.txt`

但标题却是“三本讲义精读笔记”。

这会在后续记忆中制造一种假象：仿佛已经做过原页阅读、页码核验和图表理解。

现在明确降级：

`TEXT_EXTRACTION_NOTE != VISUAL_READING != SOURCE_FIDELITY_REVIEW`

旧笔记可以作为 prior model / 搜索索引，不获得原书 Reading credit。

## 2. 第二处旧误区：71 页讲义的结构地图严重塌缩

旧笔记把《讲义71页》概括为：

- p1-p7 基础；
- p7-p9 九星；
- p9-p11 排盘；
- p11-p15 断局；

然后就结束了“71页讲义”的结构地图。

但 canonical PDF 实际还有大量正文：

- p15-p18：节气、局数、上中下元、跨节气时辰；
- p19-p22：值符/值使、八神、快速起局和完整例盘；
- p23-p32：奇仪、八门、九星、八神、九宫象意；
- p33-p49：格局、九遁、十干克应等大量规则；
- p50 起：出现暗藏飞干及另一组应用/占法内容；
- p51-p71：词讼、疾病、求财、阳宅、刑事、胜败等应用层。

因此旧结构图不是“小页码偏差”，而是**把大半本书从结构认知中漏掉**。

分类：`SOURCE_MAP_ERROR / COVERAGE_INFLATION`。

这也解释了为什么过去会感觉“这本书已经精读”，实际上只是某份文本提取的局部结构被当成了全书。

## 3. 第三处旧误区：八神体系被过度简化成“不同书各用一套”

旧笔记写：

> 善天道讲义用“真符/勾陈/太常/朱雀”（飞宫法八神名），精华本用“值符/白虎/玄武/太阴”（排宫法八神名）——两套体系混用需注意。

重新对 canonical 71 页源做 targeted visual/text review 后，这个归类过于简单，而且其中“讲义=飞宫法”与本书自身文字冲突。

同一本 71 页讲义内部至少出现：

- p3：`九神煞`，列真符、腾蛇、太阴、六合、勾陈、太常、朱雀、九地、九天；
- p19-p20：神盘说明采用值符、腾蛇、太阴、六合，并写白虎后括勾陈、玄武后括朱雀，同时记载小值符运转存在两种说法；
- p27：正文明确写“**本书用的是排宫法**”；
- p31：又写阳遁/阴遁八神名称与次序的转换，并称阳遁中的勾陈、朱雀在阴遁中为玄武、白虎。

因此当前不能把它压成：

`讲义 = 飞宫体系`，`精华 = 排宫体系`。

更诚实的状态是：

`SOURCE_INTERNAL_VARIANT / LINEAGE_SYNTHESIS_CANDIDATE / CONTEXT_REQUIRED`

需要逐段搞清楚作者是在介绍多个体系、把名称当别名、做阴阳遁替换，还是混合了不同传本/教学材料。

在搞清之前：

- 不静默互换勾陈/朱雀与白虎/玄武；
- 不把括号关系自动升级成完全同义；
- 不因为当前 runtime 已有两个 deity-system enum 就强迫原书服从项目二分法。

## 4. 第四处旧误区：把“书中有规则”升级成“项目核心资产”

旧笔记大量使用：

- `⭐最实用`
- `⭐核心资产`
- `⭐标准化流程`
- “善天道更果断”
- “善天道更完整”
- “互补：可合并使用”
- “善天道更系统化”

这些并不是 Source Fidelity 描述，而是项目当时做出的价值判断。

更严重的是，很多判断没有 matched prospective comparison。例如：

- 日干 vs 年命哪个更好；
- 三条应期 vs 五步应期能否“互补合并”；
- 主客三维度是否真的提高预测力；
- 疾病步骤是否“更系统化”就意味着更有效。

现在统一改读法：

`SOURCE HAS A STRUCTURE -> CANDIDATE HYPOTHESIS`

不是：

`SOURCE IS MORE DETAILED -> PROJECT SHOULD ADOPT IT`。

分类：`UNVERIFIED_OPERATIONAL_PROMOTION`。

## 5. 第五处旧误区：高风险断语被当成“最有价值知识”

旧笔记把“疾病预测六步骤 + 死亡应期”等列入 TOP 5 / 核心资产。

canonical p51-p71 确实包含大量疾病、死亡、犯罪、刑事、诉讼等确定性判断，这是 Source 层事实；但它不等于现实可靠性，更不应直接进入高风险 operational advice。

现在统一隔离为：

`HIGH_RISK_SOURCE_CLAIM / RESEARCH_ONLY`

可以研究它如何构造角色、关系与时间条件，但不能把“作者写得具体”当成“现实上可安全直断”。

## 6. 第六处旧误区：把同一本书默认看成一个方法层

p50 起出现“暗藏飞干”等内容，随后进入大量占法；它与 p19-p22 的快速起局/排宫法是否属于完全同一算法层，目前不能靠目录感受直接确定。

旧笔记没有识别这个潜在 method-layer shift，而是把整套材料压成一个统一“善天道体系”。

现在必须问：

- 是同一作者的补充算法？
- 是不同资料拼接？
- 是飞宫/排宫并置？
- 是另一种应用层而不改变排盘？

完整原页学习前保持 `CONFLICT_CANDIDATE / METHOD_LAYER_REVIEW_REQUIRED`。

不删除旧笔记，因为它保存了当时真实的认识状态。

可以继续保留：
