# 受约束情境推演法 v0.2-alpha

性质：**原创方法论草案 / 未验证 / 可推翻**

日期：2026-08-21

本版本不是“再造一套奇门口诀”，而是针对过去两个月反复出现的背书式解盘、反馈后修补、固定优先级、叙事漂移与验证膨胀，尝试把奇门推演改造成一个**自由度受约束、可追溯、可失败、可删规则**的推理系统。

它继承“情境推演法 v0.1”中有价值的部分，但明确废弃其中未经验证的固定折扣和“旧规则只整合不推翻”的保守假设。

---

## 一、核心命题

### 命题 A：象不是答案，象是候选特征

九星、八门、八神、天干、九宫、旺衰、空墓刑迫、伏吟反吟、格局等，只提供潜在信息。

它们必须经过：

`对象定位 -> 方法适用 -> 关系约束 -> 情境转译 -> 竞争解释 -> 结果检验`

才能进入结论。

因此：

- 生门不自动等于发财；
- 白虎不自动等于伤灾；
- 死门不自动等于死亡；
- 伏吟不自动等于失败；
- 空亡也不自动等于“待定”。

### 命题 B：真正危险的不是“不会解释”，而是“什么都能解释”

一个体系如果允许在结果后任意换用神、换起局法、换星门神优先级、调用外应、再借另一门术数确认，那么它几乎永远可以为结果找到故事。

所以本方法把“限制解释自由度”放在“增加象意词典”之前。

### 命题 C：结合实际必须与结果污染分开

现实常理、新闻、人物背景可以帮助决策，但它们也是独立信息源。

实践应用可以综合；方法验证必须拆分。

### 命题 D：一本书只能改变“我们知道作者怎么说”，不能直接改变“世界如何运行”

文献首先改变 Source Fidelity 和方法地图。只有经过独立验证，才可能改变 Empirical Support。

## 二、九阶段推演结构

### Stage 0 — Reality Baseline

先确认事实边界：

- 所问对象存在吗？
- 时间/地点/身份是否正确？
- 哪些事实已经知道，哪些才是待预测目标？
- 基础概率如何？
- 是否属于医疗、法律、金融等高风险领域？

这一步不是“用现实答案替代奇门”，而是防止对不存在或定义错误的对象进行精密推演。

### Stage 1 — Question Domain / Method Family

先定义问题属于什么任务，而不是先找一个看起来最吉或最凶的宫。

当前方法族只是候选分类，不封死为四分法：

- 状态/成败型；
- 动态/行动型；
- 空间/结构型；
- 时间/应期型；
- 多角色关系型；
- 综合型。

若某本书使用不同分类，应作为竞争 taxonomy 保存，而非强行塞回现有框架。

### Stage 2 — Setup / Layout / Time Family Freeze

反馈前冻结：

- 起局法；
- 转盘/飞宫等 layout；
- 年/月/日/时奇门 family；
- 阴阳遁与局数来源；
- 必要的门派特定规则。

若要比较多个体系，必须并行预注册，不得先看结果再挑最像的一盘。

### Stage 3 — Role Map Freeze

把“谁代表谁”写出来：

- 求测者；
- 事件；
- 对手/合作方；
- 财、工作、疾病、文书等事项角色；
- 主客关系。

每个角色注明：

`SOURCE_DEFINED / METHOD_DEFINED / CONTEXT_INFERRED`

同一角色若存在多个合理用神，应在反馈前保存竞争 Role Map，而不是结果后切换。

### Stage 4 — Eligible Feature Set

不是盘上所有东西都必须解释。

根据 Method Family 预先决定哪些信息层可以进入本次推演，例如：

- 日时干；
- 事项用神；
- 门；
- 星；
- 神；
- 宫位；
- 奇仪组合；
- 旺衰；
- 空墓刑迫；
- 伏吟反吟；
- 内外盘；
- 马星；
- 特定格局。

未进入 Eligible Set 的因素，反馈后不能临时加入充当救援解释。

### Stage 5 — Relational Inference

从“单符号断语”转向关系结构。

至少检查：

- 用神之间生克；
- 同宫/对宫/相邻关系；
- 谁作用谁；
- 作用是否有现实对应；
- 关系是否因空墓刑迫等状态改变；
- 是否存在相反信号。

这里不规定永远“星先、门后”或“开门最高”。优先级由 Stage 1 的方法族决定。

### Stage 6 — Competing Interpretation Branches

如果存在两种以上合理解释，不强行在当下消灭不确定性。

例如：

`空亡`

可能分成：

- H1：延迟/未落实；
- H2：目标落空；
- H3：暂时脱离原关系；
- H4：在本方法族中并非关键变量。

每个分支写明：

- 为什么成立；
- 什么观察最支持它；
- 什么结果会使它失败；
- 哪个竞争分支会因此占优。

最后可以给主分支，但竞争分支必须保留。

### Stage 7 — Frozen Prediction

输出必须在结果反馈前固化：

- 主结论；
- 备选结论；
- 时间范围；
- 主导证据；
- 关键不确定性；
- 方法族；
- Role Map；
- Eligible Feature Set；
- 是否使用辅助信息。

结果后不得改写原预测。

### Stage 8 — Auxiliary Context Ablation

如果任务需要现实新闻、人物背景、外应或其他术数：

先保留 Stage 7 的 method-only 版本，再形成 context-augmented 版本。

记录：

`augmentation_delta = 加入辅助信息后究竟改变了什么`

若最终正确是因为新闻已经直接提示答案，不能把命中算给奇门。

### Stage 9 — Outcome Audit / Rule Update

复盘不是“找为什么我其实没错”，而是分类错误来源：

- INPUT_ERROR
- PAIPAN_ERROR
- ROLE_MAP_ERROR
- METHOD_FAMILY_ERROR
- FEATURE_SELECTION_ERROR
- INTERPRETATION_ERROR
- TIMING_ERROR
- BASE_RATE_ERROR
- AUXILIARY_CONTAMINATION
- UNSPECIFIED_MODEL_FAILURE

然后才决定规则：

`KEEP / NARROW / REVISE / SPLIT / DEPRECATE / REJECT`

## 三、与情境推演法 v0.1 的明确差异

### 保留

- 先明确问题；
- 区分书本来源与项目推演；
- 强调关系而非单个符号；
- 允许情境转译；
- 输出不确定性；
- 反对一看到格名就下结论。

### 修改

原 `📖 / 🧠` 二分升级为：

`SOURCE / INFERENCE / EMPIRICAL_SUPPORT / CONTAMINATION`

原因：书本断语即使来源准确，也不能自动拥有“高可信度”。

### 废弃

- 旺相“全额生效”；
- 休囚“吉凶减半”；
- 四害固定加减；
- 跨问题固定 `开门 > 值符 > 生门 > 星神`；
- 凶格固定分数到阈值即裁决；
- 逢空固定解释为方向待定；
- `>=3 次 = 已验证`；
- “渐进迭代意味着不推翻任何旧规则”。

## 四、方法的真正创新点：约束自由度

过去的创新重点是“把象意翻译得更贴合情境”。

v0.2-alpha 把重点向前移动：

**先限制我能够怎样解释，再谈如何解释。**

因此评价一个方法，不只看它能不能解释结果，还看：

- 预测前需要做多少选择？
- 有多少选择可以在反馈后偷偷修改？
- 不同分析者能否复现相近的选择路径？
- 它有没有明确的失败条件？
- 错了以后会删规则，还是继续增加例外？

如果一个方法越失败，例外规则反而越多，它很可能不是在成长，而是在失去可证伪性。

## 五、理论评价的三种置信度

以后不再给一个模糊的“这条规则可信度 90%”。

至少分开：

### Source Fidelity

是否准确代表原书/原案例？

### Applicability Confidence

当前问题是否符合该规则声称的适用条件？

### Empirical Support

该规则是否在独立、反馈前冻结的案例中优于基线？

三者可以完全不同。

例如：某古籍断语可以是：

- Source Fidelity：高；
- Applicability：不明；
- Empirical Support：低/未测。

这比“古书写了，所以可信度高”更诚实。

## 六、前瞻验证设计

### 实验 A：固定全局优先级 vs 方法族优先级

同一批前瞻问题并行产生两个冻结版本：

- A：固定全局优先级；
- B：按 Method Family 预注册优先级。

比较方向、校准、错误类型，而不是只数“中了几次”。

### 实验 B：直接背书 vs 受约束情境推演

同盘并行：

- A：仅使用源规则直接判断；
- B：Stage 0-7 受约束推演。

重点比较模糊场景和冲突信号，而不是挑明显案例。

### 实验 C：Role Map Freeze

统计冻结前后：

- 反馈后换用神率；
- 预测分支数量；
- 命中率/校准变化；
- 分析者间一致性。

### 实验 D：辅助信息消融

同一问题保存：

- 奇门-only；
- 奇门 + 新闻/现实背景。

检查增益到底来自哪里。

### 实验 E：负对照

在不告知分析者的情况下，加入：

- 错时盘；
- 随机扰动盘；
- 相近但非目标时刻盘。

如果错误盘也能被解释得同样“非常吻合”，说明叙事系统的自由度过高。

## 七、梁湘润一书对本理论的攻击面

`QM-SRC-0001` 阅读时，不以“找支持 v0.2 的证据”为目标。

重点寻找能攻击以下部分的材料：

- Method Family 是否真的需要先分类；
- Role Map 是否能/应冻结；
- 是否存在比当前模型更少自由度的取用机制；
- 是否存在当前遗漏的盘式/时间体系；
- 旺衰、空墓刑迫是否有完全不同的结构角色；
- 是否存在固定优先级在严格适用域内反而优于方法族优先级；
- 是否有案例暴露“情境转译”本身就是多余自由度。

若梁书提供强反例，本理论应被修改，而不是解释梁书“其实也支持我”。

---

## 八、当前版本的失败条件

本理论若出现以下情况，应被降级：

1. 受约束情境推演长期不优于更简单的规则基线；
2. 冻结 Role Map 后性能显著下降且不能由减少后见偏差解释；
3. 方法族分类在预测前无法稳定完成，分析者一致性很低；
4. 多分支机制导致所有结果都可被某个分支覆盖，无法形成可区分预测；
5. 外部信息消融显示奇门-only 长期不增加可测信息；
6. 负对照盘与真实盘表现无显著区别。

这些不是“研究障碍”，而是本理论必须允许出现的失败结果。

## 九、当前一句话版本

> **先限制解释自由，再让象随情境而变；书本负责提出候选规则，冻结预测负责防后见，现实结果负责决定规则生死。**

版本：v0.2-alpha。尚无资格称为成熟理论，更不能称“自成一家”；只有在持续跨书、跨案例、负对照和失败检验后仍能留下来的部分，才值得进入下一版本。
