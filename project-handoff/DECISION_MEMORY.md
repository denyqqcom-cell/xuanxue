# DECISION MEMORY — 关键决策、否定路径与认知债务

本文件保存“为什么这样做”，以追加为主。它不是 current-state authority；动态事实仍以 live GitHub / CI / exact records 为准。

---

## 2026-09-05 — 建立项目级 Continuity Pack

### 决策

新增 `project-handoff/`，并把项目续接拆成：

- Stable Contract；
- Dynamic Snapshot；
- Decision Memory。

### 原因

过去跨窗口主要依赖聊天 handoff，会出现：

- SHA/CI/PR prose 已漂移但新窗口继续照抄；
- “做了什么”保存很多，“为什么这样做”保存不足；
- 工程成熟度被误当成 corpus / theory / empirical 成熟度；
- Moto/本地状态无法 fresh read 时，旧 physical evidence 被过度继承。

### 结论

新 AI 必须先 fresh verify，再决定 `HANDOFF_VERIFIED / DRIFTED / NOT_VERIFIED`。

## 2026-09-05 — Anti-KPI theory revision

### 决策

认知审查允许：`KEEP / MERGE / DOWNGRADE / SPLIT / DELETE`。

不强制“至少删除一条规则”，不强制“至少发现 N 个 latent factor”。

### 原因

强制理论变化会把研究本身变成 KPI 优化，和“盲目护旧理论”一样会污染判断。

## 2026-09-05 — World Model Before Symbols

### 决策

奇门具体事体必须 reality-first：M0→M1→M2→M3→M4。

### 关键边界

M1 不消费盘面/符号；M4 narrative 不得改写 M3 frozen prediction。

### 目的

降低 symbol-first scenario construction 和结果后解释自由度。

## 2026-09-05 — 产品层四类 provenance

### 决策

用户界面把分析内容分为：盘面事实 / 来源规则 / 项目推论 / 未经验证假设；现实输入在四类之外。

### 原因

避免 UI 把“系统算出来”“书里说”“项目推断”“还没验证”呈现成同一事实等级。

## 长期保留的认知错误清单

以下不是已解决的“历史污点”，而是每轮都要防止复发的模式：

- `书上写了 -> 现实一定如此`
- `多个来源一致 -> 已经验证`
- `某个符号出现 -> 直接现实结论`
- `已知结果后能解释 -> 有预测能力`
- `fixture/CI 通过 -> whole theory valid`
- `单一实现 -> 唯一传统标准`
- `深读过 -> formal Wave1 COMPLETE`
- `同一作品多个 carrier -> 多张独立证据票`
- `binary identical -> exact-head physical PASS`
- `unique fingerprint -> real-world independence`
- `READY_FOR_MANUAL_EMPIRICAL_REVIEW -> empirical credit`
